# TypeScript migration

TypeScript is the canonical first-party language for runtime, tools, tests and examples. Generated JavaScript and third-party artifacts are classified separately. The exact pending inventory lives in `typescript-migration.json`; it is a temporary migration backlog, not an approved final exception. Owner issue #32 remains open until that inventory is empty.

The view-delivery contract, projection client, projection contract producers/validators and independent archive verifier are migrated. The projection client separates retained state/adoption from render-plan derivation. `packages/view-contracts/implementation/*.mts` generates the existing `src` import paths and declarations. CI strictly checks the implementation and tests, regenerates tracked output and refuses a dirty result. There is no separate manually maintained declaration contract. Input decoding starts with unknown data; no any/no-check escapes are introduced.

Existing runtime tests and installed-package/browser CI remain mandatory. Remaining runtime modules, browser helpers, tests and examples must be migrated in dependency order. No package version/publication or authorization change is part of this first stage.

Projection-contract helpers are split by decoding, canonicalization, scene bindings, snapshot validation, publication and recovery. The build bundles them into the same seven runtime module paths: no executable helper can escape the runtime artifact fingerprint. Declarations are generated from strict TS. Normal wire snapshots retain the pre-migration bytes/revisions recorded in the synthetic golden fixture. New refusal tests cover accessor-backed arrays, unsafe serializer overrides, non-finite budget overrides, bounded cycle-safe freezing and synchronous read contracts.

Pending JavaScript is pinned by `pendingSha256` until migrated. New fixes must migrate its source to TypeScript, not silently refresh a permanent exception; the guard never rewrites this inventory. Generated runtime/declaration bytes are checked after rebuilding. The current migration stage changes no package versions or dependencies; publication is a separate owner release after the completed source is admitted.
